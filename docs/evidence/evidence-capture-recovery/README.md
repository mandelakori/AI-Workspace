# Capture recovery and open offline diagnosis

No model inference, remote operation, repair campaign, promotion or sealed cases.
`verification.json` records bounds, historical byte accounting and exact final
results. `proofs/` contains inert replay and intentional exhaustion receipts with
per-file sizes/hashes. Usage events there are historical replay data, not new
tokens. The 44 complete historical streams are each replayed twice; the partial
45th remains untouched. Source replay data stays in its original evidence folder.

`diagnose.py` and `authored_clock.py` are operator-authored diagnostic drivers,
not target source fixes. `pristine/`, `candidate/`, `candidate-public/` and
`nine-failures.json` preserve original-versus-candidate observations, controlled
clock results and public/upstream/interface/syntax checks in the existing offline
image. Drivers were added only to disposable copies; production/tests unchanged.

`provider-focused.log` retains an intermediate, subsequently corrected
retry-attribution failure; `intermediate-217.log` is an earlier passing suite.
`regressions.log` is the final **220/220, zero skips** result. `preservation.json`
checks historical indexes, quarantine and main. `evidence-hashes.json` covers files
here except itself. No future worker input or new trial bundle was created.
