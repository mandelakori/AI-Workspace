# Security and operational scope

- Treat TOML manifests and controller configs as operator code. Checks execute their exact argument arrays. The default requires `--trusted` or a configured local Docker image. Prefer Docker or a disposable VM for general generated or unfamiliar projects. Docker checks use an already-installed image, no network, a read-only root filesystem, a writable attempt copy, limited CPU/memory/processes and no added capabilities. Docker Desktop availability is recorded in [STATUS.md](STATUS.md).
- The harness runs as the operator on the laptop. Snapshotting and harness rules reduce exposure. They do not provide kernel isolation. Use a dedicated restricted OS account or VM for untrusted repositories and third-party harnesses. Verify an actual tool scope before enabling a new harness release.
- Native specialist jobs require `--trusted`. Use self-authored or authorized binaries. Ghidra imports the binary for static analysis. The native demonstration uses a small source allowlist before running its compiled candidate and bounds the fixture inputs and process time.
- Private checks live outside the staged input and their output does not enter retry prompts. The trusted candidate and its independent checker can still run in the same OS or container context. Use a separate evaluator identity and a process boundary for adversarial benchmarks.
- Declare precise inputs. Common secret files and harness configurations are excluded, but the tools accept project source, which may contain credentials or private data. State files contain outputs and transcripts. Keep the state directory private and control backup access.
- Existing SSH uses strict host checks and local-only forwarding. Managed SSH requires a pre-enrolled alias in known_hosts. Set credentials through environment variables. Cloud calls redact response bodies and publish selected instance fields. Provisioning and explicit termination are separate opt-ins. Ambiguous launch requests need reconciliation before new launches.
- Engineering mode authorizes only operator-declared write roots and indexed argument arrays. Its Git review tool works from an isolated index. Model-generated plans can narrow existing scope and select existing recipes. They cannot grant new permissions, modify runner configuration, or apply a patch to the source repository.
